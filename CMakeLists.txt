# The oldest macOS the shipped binaries must run on. This has to precede
# project(): CMake bakes the deployment target into the compile lines while
# configuring the toolchain, so a value set afterwards is silently ignored and
# every binary is stamped with the *builder's* OS version instead. A package
# built that way installs fine and then refuses to launch on anything older —
# `minos 26.0` on a machine whose users are on 13.x.
#
# 13.3 and not 13.0: std::format of a floating-point value calls std::to_chars,
# whose floating-point overloads only appear in the libc++ dylib shipped with
# macOS 13.3. Targeting anything older fails to compile outright with
# "'to_chars' is unavailable: introduced in macOS 13.3" rather than degrading
# gracefully, so this is a floor imposed by the standard library, not a choice.
#
# Only a default: an explicit -DCMAKE_OSX_DEPLOYMENT_TARGET still wins, and so
# does the MACOSX_DEPLOYMENT_TARGET environment variable. The environment check
# has to be explicit: CMake initializes CMAKE_OSX_DEPLOYMENT_TARGET from that
# variable inside project(), so seeding the cache beforehand would pre-empt it
# and silently drop a target the caller had every reason to think was honoured.
if(APPLE AND NOT DEFINED CMAKE_OSX_DEPLOYMENT_TARGET AND NOT DEFINED ENV{MACOSX_DEPLOYMENT_TARGET})
    set(CMAKE_OSX_DEPLOYMENT_TARGET "13.3" CACHE STRING "Minimum supported macOS version")
endif()

# Lay the install tree out for a distro package: the payload is rooted at /
# instead of /usr, because the systemd units and the /etc config sit at fixed
# absolute locations that cannot be rebased onto a /usr prefix (systemd does
# not read config from /usr/etc). See cmake/Packaging.cmake.
#
# The same reasoning applies to the macOS .pkg: `pkgbuild --install-location` is
# hardcoded to / by CPack, and the launchd plists and /etc/paths.d entry sit at
# fixed absolute locations outside any prefix. Note that this is why the prefix
# must stay `/` there too — pointing CPACK_PACKAGING_INSTALL_PREFIX at
# /opt/fastcached would work for the binaries, but an absolute install
# DESTINATION for /Library/LaunchDaemons then escapes the staging tree and
# writes to the build host's real filesystem.
#
# This is OFF by default, including on Linux, so that the ordinary
# `cmake --install --prefix /usr/local` keeps putting the daemon at
# /usr/local/bin/fastcached. Defaulting it ON rebased every developer install
# onto <prefix>/usr/bin, which is on nobody's PATH — a successful install that
# left `fastcached` reporting "command not found".
#
# Turn it ON only to build packages:
#   cmake -DFASTCACHED_PACKAGE_ROOT_PREFIX=ON ... && cpack -G "DEB;RPM"
# The CI packaging job does exactly that; see .github/workflows/build.yml.
option(FASTCACHED_PACKAGE_ROOT_PREFIX "Lay out the install tree for .deb/.rpm/.pkg packaging" OFF)

# The macOS package prefix. Single source of truth: it is spelled into the
# install destinations below, into /etc/paths.d/fastcached, into the launchd
# plists, and into the uninstaller. macOS has no FHS to follow and /usr/local is
# shared with Homebrew, so a private /opt subtree keeps the payload trivially
# enumerable — which is what makes an uninstaller possible at all, given that a
# .pkg carries no removal mechanism of its own.
set(FASTCACHED_MACOS_PREFIX "opt/fastcached"
    CACHE STRING "macOS package install prefix, relative to /")

# macOS package identity. Declared here rather than in packaging/ because both
# packaging/CMakeLists.txt (a subdirectory, which inherits this scope) and
# cmake/Packaging.cmake (include()d at this scope) read them. A plain set() in
# the subdirectory does not propagate back up, which left
# CPACK_PRODUCTBUILD_IDENTIFIER empty: receipts then registered under CPack's
# fallback identifier and the uninstaller's `pkgutil --pkgs | grep` matched
# nothing, so macOS believed fastcached was still installed forever.
#
# The bundle id must match LaunchdLabelPrefix + the lowercased default service
# name in src/Pace/Platform/ServiceControl.cpp: the daemon derives its own
# launchd label from its --service-name, and the installer scripts look the job
# up by that label. ServiceControl_test.cpp pins the derivation.
#
# Never change the bundle id once released: macOS keys package receipts and
# upgrade detection on it, the same discipline as CPACK_WIX_UPGRADE_GUID.
set(FASTCACHED_MACOS_BUNDLE_ID       "software.lastrada.fastcached")
set(FASTCACHED_MACOS_SERVICE_ACCOUNT "_fastcached")

# The compile worker's account, and deliberately NOT the daemon's above: a worker
# runs a compiler on input that arrived over the network while fastcached owns the
# cache storage, so one shared account would let a compromised compile rewrite
# every cached object -- the reason packaging/linux/fastcache-compile-node.sysusers
# declares its own too.
#
# Spelled exactly as that sysusers file and as MakeNodeServiceSpec's
# `.serviceAccount` spell it, rather than following the macOS `_`-prefix
# convention `_fastcached` does. The prefix's job is to keep the account out of
# the login window, which `IsHidden 1` already does; what it would cost is a third
# spelling of one name, across a binary, a package and a unit that never see each
# other. `ctest -R service-accounts` fails when they drift apart, on every
# platform -- because the failure mode is macOS-only and silent (issue #87).
set(FASTCACHED_MACOS_NODE_ACCOUNT    "fastcache-node")

# The worker's launchd label, on the same terms as FASTCACHED_MACOS_BUNDLE_ID
# above: LaunchdLabelPrefix + the lowercased NodeConfig::serviceName default.
# The uninstaller needs it because it removes the binary that would otherwise
# answer for itself, and a job left bootstrapped against a deleted executable is
# one nothing can reach afterwards. NodeConfig_test.cpp pins the derivation.
#
# NOT a package identifier: the installer registers no worker job (it has no
# scheduler or toolchain to register one with), so no receipt is ever filed under
# this name. It names only a job an operator installed by hand.
set(FASTCACHED_MACOS_NODE_LABEL      "software.lastrada.fastcachecompilenode")

# The tools symlinked into /usr/local/bin. /etc/paths.d only takes effect for
# LOGIN shells, so these are what make the tools reachable from an already-open
# terminal, from `ssh host cmd`, and from fish -- which never reads /etc/profile.
#
# One list, substituted into both the postinstall that creates the links and the
# uninstaller that removes them. They were two hand-written lists, and the file's
# own comment records what that cost: "The uninstaller has the mirror of this
# guard; this is the half that went missing." A tool added to one and not the
# other is either a link nothing removes or a link nothing creates.
set(FASTCACHED_MACOS_LINKED_TOOLS "fastcached fastcache-cc fastcache-compile-node fastcache-cli")

# The machine-wide configuration directory. Declared here, not in packaging/,
# for the same scoping reason as the macOS variables above: packaging/ installs
# the file into it and src/Pace/ compiles the very same path into the
# daemon's default lookup, and two sibling subdirectories cannot see each

# destinations, which are relative to CMAKE_INSTALL_PREFIX.

    CACHE STRING "System configuration directory, relative to /")

# Where dependency sources live, decided BEFORE the compiler cache is loaded: the cache module
# hands this location to fastcache-cc as its dependency root (FASTCACHE_DEPS_DIR), which is what
# lets two machines whose caches sit in different homes share objects.
#
# Share fetched dependency SOURCES across build trees, per machine (#545).
#
# Without this every fresh build tree re-clones Catch2, yaml-cpp, zstd and lz4 -- and
# this project is worked in throwaway git worktrees, so that is not a once-per-machine
# cost, it is once per branch. MEASURED on this tree, native NTFS via Git Bash, Windows
# 11, CMake 4.3.1, cold build tree each time:
#
#     no cache          45 s, 118 MB fetched into <build>/_deps
#     populated cache   24 s
#
# 21 s and 118 MB per fresh worktree, and worse where the ticket found it: over DrvFs
# (a WSL build against /mnt) the same fetch is slow enough to read as a hang, which is
# what makes it worth defaulting rather than documenting.
#
# ONLY when nothing has said otherwise. An explicit `-DCPM_SOURCE_CACHE=`, a cache entry
# from an earlier configure, and the environment variable CI sets all win -- CI points
# it inside the workspace on purpose, so that its own cache action can save and restore
# it, and silently relocating that would be a cache that stops restoring with nothing to
# say so.
#
# It degrades to TODAY's behaviour rather than failing: if no home directory can be
# determined the variable is left unset and every fetch goes into the build tree exactly
# as before. A dependency cache is an optimisation, and an optimisation that can refuse
# to configure is a worse trade than the fetch it saves.
if(NOT DEFINED CPM_SOURCE_CACHE AND NOT DEFINED ENV{CPM_SOURCE_CACHE})
    set(_fastcachedCpmHome "")
    if(DEFINED ENV{FASTCACHED_CPM_CACHE})
        # The escape hatch, named rather than implied: a machine that wants the cache
        # somewhere else (a different volume, a RAM disk) says so without having to set
        # CPM_SOURCE_CACHE on every invocation.
        set(_fastcachedCpmHome "$ENV{FASTCACHED_CPM_CACHE}")
    elseif(WIN32 AND DEFINED ENV{LOCALAPPDATA})
        set(_fastcachedCpmHome "$ENV{LOCALAPPDATA}/fastcached/cpm")
    elseif(DEFINED ENV{XDG_CACHE_HOME})
        set(_fastcachedCpmHome "$ENV{XDG_CACHE_HOME}/fastcached/cpm")
    elseif(DEFINED ENV{HOME})
        set(_fastcachedCpmHome "$ENV{HOME}/.cache/fastcached/cpm")
    endif()
    if(NOT _fastcachedCpmHome STREQUAL "")
        # `file(TO_CMAKE_PATH)` because `%LOCALAPPDATA%` arrives with backslashes, and
        # CPM splices this into paths it later quotes.
        file(TO_CMAKE_PATH "${_fastcachedCpmHome}" _fastcachedCpmHome)
        set(CPM_SOURCE_CACHE "${_fastcachedCpmHome}" CACHE PATH
            "Shared source cache for CPM dependencies (#545)")
        message(STATUS "[CPM] sharing dependency sources via ${CPM_SOURCE_CACHE}")
    else()
        message(STATUS
            "[CPM] no home directory found, so dependency sources are fetched into this "
            "build tree as before; set FASTCACHED_CPM_CACHE to share them")
    endif()
endif()

if(FASTCACHED_BUILD_TESTS)
    # Bumping this is a decision somewhere else as well. The ThreadSanitizer
    # scope is a Catch2 TAG EXPRESSION in a bash table rather than a `ctest -L`
    # selection, because `catch_discover_tests` only exports tags as CTest labels
    # from Catch2 3.8.0 on (`ADD_TAGS_AS_LABELS`) -- so the workaround has an
    # expiry date, and nothing about this line says so. `scripts/check-tsan-scope.cmake`
    # reads the version below and refuses once it moves past the one that
    # mechanism was reasoned about, with the re-evaluation and the guard that has
    # to survive it spelled out in the refusal (#312).
    #
    # SYSTEM, for the reason libunicode and core-cpp are: third-party headers are not governed
    # by this project's warning policy. Without it, the CPM route handed Catch2's headers to
    # every test TU as an ordinary include, and clang-cl reported -Wmicrosoft-cast from
    # `catch_tostring.hpp` under this project's /W4 -- sixteen times per clangcl-release build,
    # which /WX turns into a failure in code this project does not own. The find_package route
    # was already system (an IMPORTED target's include directories are), so this makes the two
    # routes agree rather than adding a special case.
    #
    # EXACT, because the test VERDICT depends on this version, not only the build. Every
    # registration carries `SKIP_RETURN_CODE 4`, which is exact only under the exit codes Catch2
    # standardised in 3.7.1 (a skip-only run exits 4, any failure 42); before that the exit code
    # WAS the failed-assertion count and a case failing four assertions scored as skipped (#1128).
    # `find_package(Catch2 <v>)` alone accepts any later 3.x -- it took Fedora's 3.13 over the 3.6
    # this said, so one machine's gate judged with another Catch2 than CI's -- and nothing about
    # that acceptance would stop at a version where the contract moved again. A distribution's
    # Catch2 is still used when it IS this version; any other is passed over for the fetch.
    CPMAddPackage(
        NAME Catch2
        GITHUB_REPOSITORY catchorg/Catch2
        VERSION 3.16.1
        FIND_PACKAGE_ARGUMENTS "EXACT"
        SYSTEM YES
    )

    # Locate the directory shipping Catch.cmake (providing catch_discover_tests)
    # and put it on CMAKE_MODULE_PATH so every test subdirectory can simply
    # include(Catch). Catch2 reaches us by one of two routes:
    #   * CPM source build  -> helpers live in ${Catch2_SOURCE_DIR}/extras
    #   * system find_package -> helpers live next to Catch2Config.cmake,
    #                            i.e. in ${Catch2_DIR}
    # CPM_USE_LOCAL_PACKAGES makes the latter the default whenever a system
    # Catch2 is installed, so both routes must be handled.
    if(Catch2_SOURCE_DIR)
        list(APPEND CMAKE_MODULE_PATH "${Catch2_SOURCE_DIR}/extras")
    elseif(Catch2_DIR)
        list(APPEND CMAKE_MODULE_PATH "${Catch2_DIR}")
    endif()

    # Every executable that links Catch2 compiles `src/tests/OffThreadAssertionGuard.cpp`, a
    # listener that ends the process at an assertion made off its test case's thread (#1211):
    # Catch2 is not thread-safe, and here not TSan-instrumented either, so such an assertion
    # damages the heap and the crash lands somewhere else, a few runs in a hundred.
    #
    # An INTERFACE source of the Catch2 target rather than a walk over executables: it arrives
    # through the link itself, `Catch2WithMain` included, so no list can leave a test binary
    # out. The CPM route's `Catch2::Catch2` is an ALIAS and the system route's an IMPORTED
    # target, so the real one is resolved first. `ctest -R off-thread-assertion-guard-coverage`
    # reads the generated link lines rather than trusting this.
    set(_catch2Target Catch2::Catch2)
    get_target_property(_catch2Aliased Catch2::Catch2 ALIASED_TARGET)
    if(_catch2Aliased)
        set(_catch2Target "${_catch2Aliased}")
    endif()
    target_sources(${_catch2Target} INTERFACE "${CMAKE_SOURCE_DIR}/src/tests/OffThreadAssertionGuard.cpp")
endif()

# libunicode, for core-cpp's terminal UI's grapheme segmentation and character
# widths (#134). Fetched here with the other third-party code, BEFORE the
# pedantic/clang-tidy includes below, for the same reason they are: those install
# -Werror -Wconversion and CMAKE_CXX_CLANG_TIDY directory-wide and must not reach
# code that is not ours to fix.
#
# 0.9.3 is a floor rather than a preference. It fixes a scan_text() bug that drops
# a zero-width codepoint following an ASCII base: the scanner splits a run at the
# ASCII/non-ASCII boundary, the zero-width codepoint arrives in the non-ASCII half
# alone and joins the cluster the ASCII half left open without widening it, so the
# reported end lags and those bytes are never emitted. The terminal UI's width
# handling is downstream of that scanner, and a terminal view that mismeasures a
# cluster corrupts every column to its right.
#
# `CPM_USE_LOCAL_PACKAGES` is ON above, so this already tries `find_package` first
# and falls back to the fetch -- the same one door yaml-cpp, Catch2, zstd and lz4
# go through, rather than a second spelling of the same policy.
if(FASTCACHED_BUILD_TUI)
    CPMAddPackage(
        NAME libunicode
        GITHUB_REPOSITORY contour-terminal/libunicode
        VERSION 0.9.3
        EXCLUDE_FROM_ALL YES
        SYSTEM YES
        OPTIONS
            "LIBUNICODE_TESTING OFF"
            "LIBUNICODE_BENCHMARK OFF"
            "LIBUNICODE_TOOLS OFF"
            "LIBUNICODE_EXAMPLES OFF"
            "BUILD_SHARED_LIBS OFF"
            # THIRD-PARTY SOURCES ARE NOT GOVERNED BY THIS PROJECT'S WARNING POLICY.
            #
            # Stated as the policy rather than as a fix for one warning, because the
            # next version of any dependency produces a different one and a
            # named-warning suppression would not cover it. Measured on CI: libunicode
            # 0.9.3's `scan.cpp:39` has an unused function template, which is
            # `-Wunused-template` -- a warning THIS project turns on and makes fatal,
            # and libunicode does not.
            #
            # The leak is specific and worth naming, because being fetched before
            # `include(PedanticCompiler)` -- which is what keeps yaml-cpp, Catch2, zstd
            # and lz4 clean -- does NOT protect this one. libunicode is a sibling
            # project of the same author and ships the SAME `cmake/PedanticCompiler.cmake`
            # with the SAME two option names. CMP0077 makes `option()` defer to a

# ----------------------------------------------------------------------------
# Code declared above these includes gets the sanitizer flags TARGET BY TARGET, and that is not a
# style choice.
#
# `Sanitizers` instruments with directory-scoped `add_compile_options`, which reaches only
# targets defined AFTER it. So a dependency added above is built with no sanitizer at all in every
# sanitizer configuration unless something hands it the flags. That was measured once, on the
# vendored endo TUI this project carried before core-cpp (#134): an object of it in the ASan build
# carried no `-fsanitize` and 0 `__asan` symbols, beside a `Pace` object carrying both, and a
# ThreadSanitizer run of `fastcache-cli-tests` reported that binary's own objects instrumented
# while the terminal wait on the pool was not.
#
# Moving those dependencies below these includes is the tidy-looking fix and the wrong one: it
# would also put `PedanticCompiler`'s -Werror and clang-tidy on code this project does not govern.
# And folding this back into directory scope would silently undo it, which is why it says so here.
#
# Read from the module's OWN variables, so a sanitizer added there reaches these targets too.
# Executables get the link flags as well, or instrumented objects would not link. libunicode and
# the other fetched dependencies stay uninstrumented. `ctest -R vendor-sanitized` asserts the result
# in the OBJECTS, where a flag that never reached a compile line would show.
#
# Two sources, each a list its owner states rather than one derived here:
# - Monocypher (#178), the vendored copy, built from cmake/Monocypher.cmake in THIS directory,
#   which states its targets beside them;
# - core-cpp (#1596), whose compiled libraries are its `CORE_CPP_TARGETS` global property. core-cpp
#   refuses `CORE_CPP_SANITIZERS` in a subproject build, so this block is the only way its code is
#   sanitized at all -- and a ThreadSanitizer run that instrumented this project's half of a race and
#   not core-cpp's half would report the one and miss the other.
if(SANITIZER_COMPILE_OPTIONS)
    set(_fcVendorTargets ${FASTCACHED_MONOCYPHER_TARGETS})
    if(NOT _fcVendorTargets)
        message(FATAL_ERROR
            "cmake/Monocypher.cmake named no targets in FASTCACHED_MONOCYPHER_TARGETS, so the sanitizer "
            "flags reached none of them. An empty list is this block having stopped working, not a "
            "cryptographic library that needs no instrumentation.")
    endif()
    get_property(_fcCoreCppTargets GLOBAL PROPERTY CORE_CPP_TARGETS)
    if(NOT _fcCoreCppTargets)
        message(FATAL_ERROR
            "core-cpp published no targets in the CORE_CPP_TARGETS global property, so the sanitizer "
            "flags reached none of them. An empty set is this block having stopped working, not a "
            "library that needs no instrumentation.")
    endif()
    list(APPEND _fcVendorTargets ${_fcCoreCppTargets})
    foreach(_fcVendorTarget IN LISTS _fcVendorTargets)
        if(NOT TARGET ${_fcVendorTarget})
            message(FATAL_ERROR
                "The sanitizer block was handed `${_fcVendorTarget}` as a target to instrument, and no such "
                "target exists. The list that named it has drifted from the targets it describes.")
        endif()
        get_target_property(_fcVendorTargetType ${_fcVendorTarget} TYPE)
        if(_fcVendorTargetType MATCHES "^(OBJECT_LIBRARY|STATIC_LIBRARY|SHARED_LIBRARY|MODULE_LIBRARY|EXECUTABLE)$")
            target_compile_options(${_fcVendorTarget} PRIVATE ${SANITIZER_COMPILE_OPTIONS})
        endif()
        if(_fcVendorTargetType MATCHES "^(SHARED_LIBRARY|MODULE_LIBRARY|EXECUTABLE)$")
            target_link_options(${_fcVendorTarget} PRIVATE ${SANITIZER_LINK_OPTIONS})
        endif()
    endforeach()
endif()

# ## Why ctest learns a Catch2 skip from `SKIP_RETURN_CODE 4`, and why the Catch2 pin is EXACT
#
# Every `catch_discover_tests` registration in this tree carries `SKIP_RETURN_CODE 4`, and
# under the Catch2 this tree pins that is EXACT. Catch2 3.7.1 standardised its exit codes,
# and 3.9.0 made them Session API constants (`catch2/catch_session.hpp`): a run whose every
# case skipped exits 4 (`AllTestsSkippedExitCode`), ANY assertion failure exits 42
# (`TestFailureExitCode`) whatever the count, and a run that ran nothing exits 2. So 4 means
# skipped-and-nothing-failed, and a case that skips one SECTION and fails another exits 42
# and is scored failed. `catch-skip-exit-contract` runs those shapes on every build.
#
# **Before 3.7.1 it was KNOWN BROKEN (#1128), and the EXACT pin is what keeps it fixed.**
# Catch2's exit code was then its failed-assertion count, clamped at 255, so a case failing
# exactly four assertions exited 4 and ctest scored it *skipped* -- measured through real
# ctest on 3.6.0, inside `100% tests passed`, in all five Catch2 binaries; and no other
# status was free to move the signal to, since every value in 1..255 was reachable as a
# count. A version-COMPATIBLE `find_package` takes any 3.x a machine has installed -- it
# took Fedora's 3.13 -- and an older one brings the collision back with no line of this tree
# changed. The exit contract is a property of the Catch2 BUILD, so the pin names one.
#
# What the 3.6.0 investigation measured about the other channels is still true, and it is
# why the mechanism is the exit code and never a pattern:
#
# **The output is shared with the subject.** `SKIP_REGULAR_EXPRESSION` is
# a substring search over the case's ENTIRE output -- names, `INFO` messages,
# stringified expressions -- none of which this project controls. A case that only
# FAILS, carrying the literal summary text in a message, is scored SKIPPED. Closing that
# needs a line-start anchor, and both spellings are unavailable:
#
#   * `^` is `cmd.exe`'s escape character, and this value is passed on a COMMAND LINE by
#     `catch_discover_tests`, which on Windows cmd parses;
#   * a literal newline arrives EMPTY through cmd -- measured, `rc=0`, argument `[]` --
#     and an empty `SKIP_REGULAR_EXPRESSION` matches every line, so the remedy degrades
#     into every failing test scoring as skipped. Silently, at exit zero.
#
# **Composing them does not exist.** `FAIL_REGULAR_EXPRESSION` does NOT outrank
# `SKIP_RETURN_CODE` -- measured; with both set, a four-failure case on 3.6.0 was still
# `***Skipped`.
#
# `src/tests/CatchSkipCanary.cpp` carries the shapes, and `catch-skip-exit-contract` runs
# them and asserts the contract `SKIP_RETURN_CODE 4` rests on, so a Catch2 that changes its
# exit codes again is a red rather than a silent false GREEN. The whole argument is in
# `.agent/rules/testing.md`.
