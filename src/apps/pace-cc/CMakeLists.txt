# pace-cc — the sccache-style compiler launcher, plus its unit tests.
#
# The launcher only needs the path-canonicalization + compile-value codec, the
# shared usage renderer, and the two leaf platform probes -- none of which have
# third-party dependencies. We compile those few Pace sources directly into
# the tool rather than linking the whole Pace static library, so the
# launcher pulls in NO vcpkg deps (zstd, lz4, yaml-cpp). That keeps it a small,
# self-contained binary and lets it link the CRT statically without a
# runtime-library mismatch against vcpkg objects.
#
# Cli/UsageDoc.cpp is what makes `pace-cc --help` render and colorize
# exactly like `pace-kv --help`; Platform/Terminal.cpp decides whether to,
# and Platform/Environment.cpp is the one place the environment is read, so the
# launcher no longer needs its own copy of that dance. Platform/Registry.cpp is
# there for the same reason one layer over: locating an MSVC toolchain without an
# inherited `INCLUDE` means reading the Windows SDK's installed roots, and a
# second copy of the two-call size dance and the WOW64 view is a second chance to
# get either wrong. It compiles to nothing on POSIX, so it costs that build a
# translation unit and no dependency.
#
# Platform/ReplacingRename.cpp is the one rename a written file is moved over the one it replaces with:
# POSIX semantics on Windows, so a reader sharing delete does not refuse it, and the classic rename only
# where a filesystem has none -- said, never decided in silence. The node's durable writer is built on
# it too, and two copies of it were two places for a fix to land in one and miss the other. Standard
# library and the Win32 API only.
#
# Cli/Duration.cpp is the one duration grammar every time-valued setting is written in (#1402). The launcher's
# timeout environment variables are such settings, and a second parser here would be a second answer to what `2s`
# means. A unit table and two functions over <charconv> and <chrono>: no dependency either.
#
# Note what is NOT here: Core/Crc32c.cpp. It was carried for the cache key, and
# the key no longer uses it -- Core/MurmurHash3.hpp replaced the four salted
# CRC32C runs that gave a 128-bit-wide key 32 bits of strength (issue #63), and
# it is header-only, so the component that replaced a compiled row costs none.
# The remaining CRC32C users are all daemon-side page and record checksums.

set(_pace_cc_core
    "${CMAKE_SOURCE_DIR}/src/Pace/Cli/Duration.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Cli/UsageDoc.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/CompileCache/PathCanon.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/CompileCache/CompileValue.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Core/Base64.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Core/Compression.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Core/CpuFeatures.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Core/Ed25519.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Core/SecureBytes.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Core/Sha256.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Metrics/IMetricsSink.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Platform/Environment.cpp"
    "${CMAKE_SOURCE_DIR}/src/Pace/Platform/NarrowText.cpp"

# The launcher's TCP client -- the blocking pair it dials with, and the event loop and
# connector it dials through without blocking -- is core-cpp's `core::net` (#1596), linked
# below, rather than a copy of its own, because a copy is what went wrong: this tree had three
# implementations of "dial, then send and receive whole messages", and the one nobody compiled
# (compile-cache-testclient) was IPv4-literal-only, unbounded and unprotected against SIGPIPE.
#
# It costs the launcher nothing it was avoiding. The rule this file exists to protect is that
# pace-cc does not LINK Pace -- so it stays free of yaml-cpp and OpenSSL -- and
# `core::net` links only core-cpp's own base, platform and async libraries and the platform's
# threads and sockets. core-cpp's TLS is a separate target, `core::net_tls`, which this does not
# link.

# Core/SecureBytes.cpp is here because the lease validator's collaborators hold key
# material in it, and the validator is in WorkerProtocol.cpp -- this directory's file,
# compiled into both binaries -- so the type key material lives in has to be linkable in
# a launcher build too. It is one row for the same reason Sha256 is: the alternative is a second
# zeroing primitive, and two of those is one that gets it wrong.
#
# It costs nothing the rule above protects. SecureBytes.hpp reaches <cstddef>,
# <memory> and <vector>; the .cpp adds <cstring> and, on Windows, windows.h -- which
# is why the platform selection is in a .cpp at all and not in the header every
# credential holder includes.

# Core/Sha256.cpp and Core/Base64.cpp are what a signed lease token was made of when
# it was an HMAC under the retired pre-shared key, and Base64 still renders it as text; Sha256
# keys the spent-grant set (src/Pace/Distributed/LeaseToken.hpp). The worker's
# protocol is WorkerProtocol.cpp, which lives in THIS directory and is compiled into
# both binaries, so the verification half is linked into a launcher build too.
#
# Core/Ed25519.cpp is what a grant is signed with since #178: the issuing voter's
# own identity key, verified against the roster. It is the second deliberate
# exception to the no-third-party rule, after Compression below, and it costs one
# static library: pace-monocypher, a verbatim vendored copy built as C++ with no
# dependency of its own (cmake/Monocypher.cmake). Linked below for both targets that
# compile these rows. The alternative -- a launcher build that cannot verify what
# the worker it shares a file with must -- is not one.
#
# They cost nothing the rule above protects. Sha256.hpp reaches only the standard
# library; Sha256.cpp adds Core/Endian.hpp (already here through
# CompileCacheWire.hpp), Core/EnumTable.hpp and Core/Ranges.hpp, all header-only and
# std-only, and the compiler's own <immintrin.h> or <arm_neon.h>. Core/CpuFeatures.cpp
# is how Sha256.cpp picks its engine at run time (#1420), and reaches the compiler's
# own <intrin.h> or <cpuid.h> on x86-64 and <sys/sysctl.h> on arm64 macOS -- no
# windows.h. Base64 reaches the standard library alone. No vcpkg package, no OpenSSL
# -- which is the point of having SHA-256 in this tree at all, since
# PACE_ENABLE_TLS is off by default and peer authentication is not optional.
#
# Core/Compression.cpp is the first of the two rows here that are NOT dependency-free
# (Core/Ed25519.cpp, above, is the second), and it is a deliberate exception to the
# rule the comment above states.
#
# Distributed compilation sends a preprocessed translation unit over the network --
# several megabytes for an ordinary C++ TU, on the hot path of a parallel build --
# and shipping that uncompressed is the difference between distribution being worth
# switching on and not. The codec table is also already the daemon's, so the
# alternative was a second compressor in the launcher, which is worse: two
# implementations of one wire format, one of them untested against the other.
#
# What it costs, stated so nobody rediscovers it: the launcher's build now needs
# zstd and lz4, which are CPM-fetched rather than vcpkg -- and they are built with
# CMake's default MSVC runtime, which the static-CRT link below has to work around
# in Debug (see the MSVC_RUNTIME_LIBRARY property for what it costs and why the
# obvious fix is unavailable). It does mean the launcher
# no longer builds without a network on a cold CPM cache, and it inherits the macOS
# constraint the packaging job already carries: CPM_USE_LOCAL_PACKAGES=OFF, or a
# Homebrew shared zstd gets linked and `otool -L` fails the "nothing outside
# /usr/lib" assertion.
#
# PACE_ENABLE_COMPRESSION=OFF stays a working configuration: the codec table
# compiles without either library, Identity is always available, and the wire
# negotiation falls back to it -- so such a launcher still dispatches, just without
# compressing. That is asserted, not assumed.
if(PACE_ENABLE_COMPRESSION)
    if(TARGET libzstd_static)
        set(_pace_cc_zstd libzstd_static)
    elseif(TARGET zstd::libzstd_static)
        set(_pace_cc_zstd zstd::libzstd_static)
    elseif(TARGET zstd::libzstd_shared)
        set(_pace_cc_zstd zstd::libzstd_shared)
    endif()
    if(TARGET lz4_static)
        set(_pace_cc_lz4 lz4_static)
    elseif(TARGET LZ4::lz4_static)
        set(_pace_cc_lz4 LZ4::lz4_static)
    elseif(TARGET lz4::lz4)
        set(_pace_cc_lz4 lz4::lz4)
    endif()
endif()

# Fully static, copy-anywhere binary: statically link the MSVC C++ runtime so
# the launcher depends only on always-present Windows system DLLs (WS2_32,
# KERNEL32) and needs no VC++ redistributable on build agents. On by default;
# turn off to use the shared runtime (smaller binary, needs the redist).
option(PACE_STATIC_LAUNCHER "Statically link the CRT into pace-cc" ON)

add_executable(pace-cc
    main.cpp
    ${_pace_cc_sources}
    ${_pace_cc_core}
)
target_include_directories(pace-cc PRIVATE "${CMAKE_SOURCE_DIR}/src")
target_compile_definitions(pace-cc PRIVATE
    PACE_CC_VERSION="${PACE_VERSION_STRING}")
if(PACE_ENABLE_COMPRESSION AND _pace_cc_zstd AND _pace_cc_lz4)
    target_link_libraries(pace-cc PRIVATE ${_pace_cc_zstd} ${_pace_cc_lz4})
    target_compile_definitions(pace-cc PRIVATE PACE_COMPRESSION_ENABLED=1)
endif()

# Core/Ed25519.cpp's primitive; see the comment on `_pace_cc_core`.
target_link_libraries(pace-cc PRIVATE pace-monocypher)

if(WIN32)
    target_link_libraries(pace-cc PRIVATE ws2_32)
endif()

# `core::net::ThreadedAddressResolver` runs `getaddrinfo` on a pool of its own, because
# it takes no timeout and a wedged resolver would otherwise stall every translation
# unit in the build. That is the one thing this launcher genuinely needs a thread
# for, and it needs the platform's thread support linked to get it.
#
# NOT a departure from the rule this file exists to protect. That rule is about not
# linking Pace and therefore not dragging in yaml-cpp, OpenSSL or the reactor's
# transitive world; the C++ standard library's own threading support is not that
# kind of dependency, and a static launcher still links no third-party code. It is
# named explicitly rather than left to glibc folding pthread into libc since 2.34 --
# that happens to work on the distributions CI uses and is not something to rely on.
find_package(Threads REQUIRED)
target_link_libraries(pace-cc PRIVATE Threads::Threads)
# core-cpp's /MT twins where this launcher takes the static CRT -- Release under
# PACE_STATIC_LAUNCHER, per the MSVC_RUNTIME_LIBRARY property below -- and the ordinary targets
# everywhere else. A mix is refused at link time (`/failifmismatch: RuntimeLibrary`), and the
# daemon, which links the DLL CRT, links the ordinary ones. `core::async` is header-only, so it has
# no twin.
if(MSVC AND PACE_STATIC_LAUNCHER)
    target_link_libraries(pace-cc PRIVATE core::async "$<IF:$<CONFIG:Debug>,core::net,core::net_mt>")
else()
    target_link_libraries(pace-cc PRIVATE core::async core::net)
endif()
# The event loop and its platform sockets are core-cpp's `core::net` (#1596), linked above, so
# the launcher can dial without blocking -- see `core::net::IConnector`.
#
# WIN32_LEAN_AND_MEAN / NOMINMAX / _WIN32_WINNT are NOT optional and NOT
# inherited: they are PUBLIC on the Pace target, and this binary
# deliberately does not link Pace. Without them the Windows build fails
# outright on the first translation unit that reaches <windows.h> before
# <winsock2.h>, which pulls in winsock.h first -- the
# classic redefinition. Platform/Terminal.cpp already includes <windows.h> here
# and survives only because nothing in that translation unit also wants winsock2.
if(WIN32)
    target_compile_definitions(pace-cc PRIVATE WIN32_LEAN_AND_MEAN NOMINMAX _WIN32_WINNT=0x0A00)
endif()


if(PACE_STATIC_LAUNCHER AND MSVC)
    # CMP0091: MSVC_RUNTIME_LIBRARY selects /MT(d) vs /MD(d). Static so the CRT is
    # baked in and the shipped launcher needs no redistributable -- it is fetched as
    # a bare binary by PACE_AUTO_INSTALL, onto machines that have no reason to
    # carry one.
    #
    # DEBUG IS THE EXCEPTION, and it is not a preference. zstd and lz4 are CPM-built
    # here and take CMake's default runtime (the DLL one), because the Pace
    # library links the very same static libraries and the daemon's vcpkg
    # dependencies are dynamic-CRT builds -- so those two targets cannot both be
    # satisfied by one setting. In Release nothing breaks: the CRT entry points zstd
    # calls resolve out of whichever CRT the exe links. In Debug they do not, because
    # `assert()` references `__imp__wassert`, which exists ONLY in the DLL CRT, and
    # the launcher stopped linking at all the moment compression was added to it:
    #
    #     zstd_static.lib(zstd_compress.c.obj) : error LNK2001:
    #         unresolved external symbol __imp__wassert
    #
    # Windows CI builds Release only, so `cl-debug` and `clangcl-debug` -- both
    # documented in AGENT.md -- were broken for every Windows developer while every
    # job stayed green. The Debug launcher is a developer artefact and never shipped,
    # so it takes the runtime its dependencies were built with; the artefact that IS
    # shipped keeps the static CRT it has always had.
    set_property(TARGET pace-cc PROPERTY
        MSVC_RUNTIME_LIBRARY "$<IF:$<CONFIG:Debug>,MultiThreadedDebugDLL,MultiThreaded>")
endif()

install(TARGETS pace-cc
    RUNTIME DESTINATION "${PACE_INSTALL_BINDIR}"
    COMPONENT "${PACE_APP_COMPONENT}"
)
