# The C-style loops in production sources that nobody has decided about yet, and the issue that
# will decide them. Read by `scripts/check-test-loops.cmake`.
#
# rule|file|count|issue
#
# A row here makes a DIFFERENT claim from a row in `PaceTestLoopExemptions`. An exemption
# says *this site is right and must stay, here is why*. A row here says *nobody has decided about
# these yet*. Spelling the second like the first would put every site below behind a word that
# means "decided", and the only reason an undecided row is safe at all is that the check tallies
# these and prints the total per issue on every run.
#
# The count was spelled out here as `148 sites` and went stale the first time a batch landed,
# which is the defect this file's own line about totals warns against: a figure in prose tracks
# nothing and reads as authoritative. The check derives it.
#
# It is a RATCHET and it turns one way. More sites in a file than its row records is a NEW site
# and is refused -- the answer is to convert it, never to raise the number. FEWER is a row that
# has stopped describing the file, refused as stale, so a conversion is recorded in the same
# change that makes it and the number it left behind is not room for the next arrival.
#
# Keyed on a COUNT per (rule, file), deliberately not on a line number, which churns on any edit
# above a site. What that leaves open, stated rather than engineered away: one site removed and
# another added in the same file under the same rule is a wash this cannot see. A key that could
# see it would have to be the header text, and a `for` header contains a `;`.
#
# ONE row per rule per file. Two are refused by name: the scan would match the first and read
# the second as a site that had been converted, so the count governing the file would be
# whichever row came first.
#
# Blank lines and `#` lines are ignored. Nothing else is: a line this reader cannot split is
# refused, because a row read as a count of zero waves through every site in its file.
#
# The check refuses a row whose `issue` is not shaped like one, and deliberately does not ask
# GitHub whether that issue is OPEN -- a hygiene check that needs the network is one that cannot
# run. A row naming a CLOSED issue would be a row whose owner says the work is done, which is
# the `RefuseUntriaged` hazard exactly. That liveness IS checked, one level up: every issue
# named here also has an `## Open work` entry in `.agent/rules/testing.md`, and
# `ctest -R rulebook-open-work` resolves those and refuses one that has been closed. Adding a
# network probe here would be a second source of truth for the same fact.
#
# No total is written here. `check-table-totals.sh` reads only markdown under `.agent/`, so a
# marker in this file would read as enforcement that nothing performs -- and the figures it
# would state are DERIVED by the check on every run and printed there, which is the one place
# they cannot drift from the rows.
#
# EMPTY, and deliberately so: #1452 decided every production site this file held -- each one
# converted, or moved to `PaceTestLoopExemptions` with the reason it stays. The check says
# so on every run (`backlog: empty`) rather than printing nothing, because a tally that simply
# stops appearing reads the same as one that stopped being computed. A NEW site is converted or
# exempted, never added here: a row comes back only when the scan's SCOPE widens over sites
# nobody has decided about, naming the issue that will -- and the ratchet above applies unchanged.
